# Decisions

One line for each decision: date — decision — why. Newest at the bottom.

- 2026-11-07 — Local-first: the UI reads and writes Dexie only; Supabase is a background sync target — works offline, instant UI, simple single-user conflicts.
- 2026-11-07 — Supabase (Google login + Postgres + RLS) instead of Google Drive app folder or Neon — login and database in one, no server needed; Drive would need a hand-written sync engine, and Neon would need our own API server.
- 2026-11-07 — `output: "export"` (static SPA), no server code — free hosting anywhere; the same build goes into Capacitor for Android/iOS.
- 2026-11-07 — Turned off `cacheComponents` / `partialPrefetching` (on by default in Next.js 16) — they need a Node server and conflict with static export.
- 2026-11-07 — Language switches on the client (no `/bn` `/en` routes) — static export has no middleware to detect the locale.
- 2026-11-07 — Money stored as integer paisa; our own lakh-grouped formatter instead of `Intl` — exact maths, and identical output on every browser.
- 2026-11-07 — Hind Siliguri bundled with @fontsource instead of next/font/google — works offline and in app builds, with no network call during the build.
- 2026-11-07 — Categories got extra fields beyond the plan (`key`, `is_system`, `hidden`) — needed for bilingual defaults, undeletable built-ins and hiding (spec §4).
- 2026-11-07 — The server sets `updated_at` with a trigger — a wrong phone clock can't win sync conflicts (spec §10).
- 2026-11-08 — First run seeds one Cash wallet (named in the first-run language) and the bilingual default categories; seeding counts deleted rows too, so it never re-adds them — step 2 needs a wallet and categories before their screens exist (step 3). Step 7 must dedupe seeded rows by `key` when a second device signs in.
- 2026-11-08 — shadcn/ui with the `base-nova` preset (Base UI primitives, the `cn` package from shadcn-ui); kept Hind Siliguri instead of the Geist font the init adds — offline font, Bangla support.
- 2026-11-08 — Dates older than yesterday use the native `<input type="date" max=today>` instead of a custom calendar — no extra code, the phone's own picker; the week-start question no longer applies.
- 2026-11-08 — Dark mode follows the phone via next-themes (`class` strategy, needed by shadcn) until the Settings theme switch (spec §8).
- 2026-11-08 — "Last used wallet" = the wallet of the most recently created entry, not a stored setting — nothing extra to sync.
- 2026-11-08 — Wallets and categories reorder with up/down buttons instead of drag — no new dependency, accessible, works on every phone; drag (e.g. @dnd-kit, loaded only on those screens) can come later if users ask.
- 2026-11-08 — "Balance adjustment" stays one system category used for both income and expense adjustments — it's hidden from pickers and excluded from totals, so its `type` never matters; no migration needed.
- 2026-11-08 — The "adjustment" category is not listed on the Categories screen (internal); other built-ins can be renamed and hidden but not deleted.
- 2026-11-08 — Periods use month start day 1 (`DEFAULT_START_DAY` in `src/lib/period.ts`) until the Settings screen (new roadmap step 5b) — the plan had no step for Settings; `period.ts` already handles any day 1–28 and is tested with day 7.
- 2026-11-08 — The add sheet and Recharts load lazily (`next/dynamic`); the sheet chunk is preloaded 1 s after start — Home's first-load JS fell from 292 KB to 259 KB (budget 300 KB).
- 2026-11-08 — One app-wide add/edit sheet lives in `AppShell` (layout), opened with `useOpenEntry()` — the + button is on every tab and rows on any screen can open it.
- 2026-11-08 — Tab bar is Home · Transactions · More; Budgets is added in step 5, so no tab leads to a missing page. Wallets and Categories live under More.
- 2026-11-08 — Day totals and the Transactions footer show the signed net (Income − Spent, same rules as Home), so transfers and adjustments don't count there either.
- 2026-11-08 — Budgets count transfer fees (in "Fees & charges" and Overall) but never transfer amounts — matches Home's Spent; spec §5 "transfers never count" read as the amount.
- 2026-11-08 — Budget copy-forward is month-level at read time (`budgetsFor`); the first edit in a month copies the carried-over rows into it, and removing a budget sets `limit_paisa` to 0 instead of deleting — so editing November never changes October, and a removed budget doesn't come back from an earlier month.
- 2026-11-08 — Budget bar colours follow spec §5 (green < 75%, amber 75–99%, red ≥ 100%), not the "red over 90%" line in the plan's Screens table.
- 2026-11-08 — The settings row is created the first time a setting is changed; screens get `startDay` from `useEntries` and keep only a period key, so changing the start day updates every screen at once.
- 2026-11-08 — CSV export moved out of step 5 to a later step (5c), at the user's request.
- 2026-11-08 — Offline caching uses our own small service worker (`scripts/build-sw.mjs` writes `out/sw.js` after `next build`) instead of Serwist — Serwist's Turbopack setup needs a Route Handler (breaks hard rule 1) and its other setup needs the webpack build. The worker pre-caches every exported file (except .woff/.map), serves cache-first, and a new version waits until old tabs close.
- 2026-11-08 — The service worker registers only in production builds (`npm run build` + `npm run preview`), never under `next dev`. Hosting must serve `/sw.js` with `Cache-Control: no-cache` so updates are picked up (step 1c).
- 2026-11-08 — Persistent storage is requested only when running installed (standalone) — Chrome grants it silently there; asking on every load would show a Firefox popup.
- 2026-11-08 — Placeholder ৳ icons are generated once by `scripts/make-icons.mjs` with the renderer bundled in Next (`next/og`) and committed to `public/icons/`; no image package added.
- 2026-11-08 — Quick add (spec §9): `/add?…` opens the app-wide add sheet over Home via `useOpenEntry(null, prefill)`, then swaps the address to `/` with `history.replaceState` so back/refresh don't reopen it; parsing lives in `src/lib/quickAdd.ts`. Wallets have no key, so `wallet=` matches the name, then the provider (bkash), then the kind (cash). `cat=` without `type=` takes the category's type (`cat=salary` opens Income).
- 2026-11-08 — Android one-tap add uses manifest `shortcuts` (long-press the installed icon → drag "Add expense" to the home screen). The iOS Shortcut is postponed (roadmap 8b) at the user's request.
- 2026-11-08 — Apple-style "Liquid Glass" uses only the frosted level: a `glass` utility in `globals.css` (see-through background + `backdrop-filter: blur saturate`, solid when unsupported, Reduce Transparency or More Contrast), tried on the tab bar first at the user's request. The SVG refraction effect is skipped: Chromium-only (Safari/iOS ignore it), heavy on budget phones' GPUs. Glass goes on floating controls only, never behind amounts or lists.
- 2026-11-08 — Glass extended to every floating surface: tab bar, Transactions totals footer, add/edit sheets (drawer), toasts and the + button (tinted with `--glass-tint`). Cards, lists and page headers stay solid — headers scroll with the page, so glass would show nothing there. Toasts and the + button use `glass!` because sonner/Button set their own background; sonner's `--normal-bg` stays solid because it also colours toast button text.
- 2026-11-08 — Official logo is H3 "Budget card" from the logo canvas (https://claude.ai/artifact/M7gB5ZT5Xf5MhGAYdTgkEx): a white wallet card with ৳ and a 4-colour budget bar, two faded cards behind, on green #0B7A57. `scripts/make-icons.mjs` draws it (next/og, no new package) into `public/icons/` and `src/app/favicon.ico` (32 px PNG wrapped as ICO, replacing the Next default). Manifest `theme_color` is now #0B7A57. No vector file is kept: the script is the source.
- 2026-11-08 — Step 5b: Digits and Theme are rows on the More tab (with Language and Month starts on), not a separate Settings screen. Digits: a manual choice is stored in localStorage `mm.digits` and **resets to the language's default whenever the language changes** (spec §8 default rule). Theme: three buttons (Light / Dark / Match phone) driving next-themes, which stores it and prevents a flash on load; `AppShell` recolours the `theme-color` metas so a manual theme also colours the status bar. Every change is also recorded in the settings row (`saveSettings`) for sync in step 7; localStorage stays the source until then.
- 2026-11-08 — Official app name: **PaiPoisha** (English) / **পাই-পয়সা** (Bangla), from *পাই-পয়সার হিসাব*, "every last paisa". Title and manifest name: "PaiPoisha — পাই-পয়সার হিসাব". The home-screen label (`short_name`, iOS `appleWebApp.title`) is the Latin "PaiPoisha": one label for both languages, readable in store search. The Home heading follows the language (`app.name`). Internal names are unchanged on purpose: the Dexie database stays `money-management` (renaming it would strand every user's data), as do the npm package name and the `MoneyDB` class. Store, domain and trademark availability were not checked.
- 2026-11-08 — Hosting (step 1c): **Vercel Hobby** at https://paipoisha.vercel.app/, deployed from GitHub (user's choice over the suggested Cloudflare Pages; Hobby is non-commercial only, so revisit before charging money). `vercel.json` sets `framework: null`, `buildCommand: npm run build`, `outputDirectory: out`, so Vercel uploads `out/` as plain files. Vercel's Next.js preset doesn't fit a static export plus a post-build `sw.js`: with output `out` it fails looking for `routes-manifest.json`; with the default output it serves the pages but not `sw.js`. Vercel's default `Cache-Control: public, max-age=0, must-revalidate` already meets the service worker's no-cache rule.
- 2026-11-08 — Add sheet decluttered after a phone report (only one row of categories showed on an iPhone; on a 360×560 budget Android the middle area was 0 px). The sheet now opens almost full height (`100dvh − 1rem`), the title is screen-reader only, pad keys are 44 px, and the **number pad steps aside** when the user taps or focuses anything below the amount once an amount is typed. Tapping the amount (or fee) brings it back; it also comes back on an amount/fee error and after Save & add another. Amount + category + Save is unchanged.
- 2026-11-08 — Step 7 sync design: `src/sync/engine.ts` does one cycle (push dirty rows in batches of 500 → pull by **keyset paging on (updated_at, id)** with one cursor per table in `meta`, holding the server's own values). Offset paging could skip rows that change mid-pull, and a plain `updated_at > last` could split a 500-row upsert that shares one server timestamp. Pulled timestamps are converted to the app's `…Z` ms format so string comparisons hold. The engine talks to the cloud only through a 3-call `Remote` (`src/sync/remote.ts`), so tests use an in-memory server. `src/sync/runner.ts` (triggers, single-flight lock with one queued follow-up, 5 s / 30 s / 2 min retries, Error after the third failure) and supabase-js are **lazy-loaded** by the app shell, so they never count toward first-load JS. The UI reads status from `src/sync/status.ts`, which has no Supabase import. Auth uses PKCE (`flowType: "pkce"`), with the session in localStorage and a client-only `/auth/callback/` page. Sign-out uses `scope: "local"` so it works offline, then `db.delete()`.
- 2026-11-08 — Step 7 first sign-in merge (user's choices): rows never uploaded have `user_id` null. On the first sync of an account on a phone, the account's data is pulled first; then the phone's default categories merge into the account's by `key` (entries and budgets are moved over), an untouched local Cash wallet (no entries, ৳0 opening) is dropped, and the phone's settings row gives way to the account's. Those local rows are hard-deleted, which is safe because they never reached the server. The account's language, digits and theme are then applied on the phone, with the toast "Added N entries from this device". Migration `0002` allows `limit_paisa = 0` on budgets, since the app uses 0 to mean "removed".
- 2026-11-08 — Welcome page instead of the spec's 3 onboarding screens (user's choice): a bilingual page with a language switch, Continue with Google and Skip for now, shown **only on a brand-new phone** (no entries, not signed in, Skip not tapped, and only in a build with Supabase keys). Phones already in use go straight to Home and sign in from More → Account. Nothing is seeded behind the welcome page. Picking wallets and opening balances during onboarding is not built.
- 2026-11-08 — UI feedback round after step 7 (user's requests): **Bangla digits ০–৯ use Noto Sans Bengali** through a `Bangla Digits` @font-face limited by `unicode-range` (`@fontsource-variable/noto-sans-bengali`, one 108 KB variable file, fetched only when a Bangla digit is on screen). Hind Siliguri's ১ looks almost exactly like ৬; all other text stays Hind Siliguri. The add sheet's **number pad opens only when the amount (or fee) is tapped**. The **category grid is now one native `<select>`** with every category of the type, most used first; the phone's own picker is accessible and testable. This adds a tap to the "amount + 3 taps" target, at the user's request. **Categories are ranked by drag** with `@dnd-kit` (grip handle only, so the list still scrolls; keyboard Space + arrows; screen-reader text translated), replacing the up/down buttons decision above for categories. Wallets keep up/down. The **tab bar floats** as a rounded glass pill above the bottom edge (`max(0.75rem, safe-area)`); the + button, the Transactions footer and the page padding follow it.
- 2026-11-08 — Sync status honesty: while a failing sync is retrying, the status now shows **Syncing…** (it used to show "Synced", even when no sync had ever succeeded), and from the third failure More → Account shows **the error message itself** under "Couldn't sync". This came from investigating "web data not in the iPhone app": the live build has the keys, the pull queries are valid on the real server, and local rows match the Postgres columns, so the remaining causes are outside the code (which origin/browser holds the "web" data, and whether that origin is signed in). Note that localhost, the Vercel site, iPhone Safari and the iPhone home-screen app are four separate local databases.
- 2026-11-08 — Category dropdown v2: the native `<select>` list ignored dark mode on iPhone/Chrome (white list, light text) and can't show icons, so it is now shadcn `select` (Base UI): themed, with icon + name in the trigger and in every item, opening below or above the field (`alignItemWithTrigger={false}`). Its positioner sits at `z-[60]` in `ui/select.tsx`, above drawers (`z-50`); otherwise it opened behind the add sheet. **Demo data (dev only, user's choice)**: More → Developer → Add / Remove demo data, shown only under `npm run dev` (the production build drops the code) and disabled while signed in, so demo rows never reach a real account. It adds 3 wallets, about 90 days of entries, salary top-ups, ৳5,000 bKash cash-outs with the ৳93 fee, and this month's budgets, all from a fixed seed, with every wallet staying positive. The row ids are stored in `meta.demo_rows`; Remove hard-deletes never-uploaded demo rows and soft-deletes any that synced.
- 2026-11-08 — **Toasts for every save, delete and failure** (user's choices): all success and error toasts go through `components/common/notify.ts`. Success lasts 2 s, errors 5 s. Every toast has an × and sits below the notch; sonner's screen-reader labels are translated. **Validation is inline + toast**: the red line stays by the field and `notify.invalid` repeats the message, using one id so repeated taps replace rather than stack, and the next success clears it. New success toasts cover wallet, category and budget add/update/hide/show/delete. Failures that were silent now toast: entry delete and its Undo, sync turning to Error (once per streak, with Retry, using the `sync` id so it shares a slot with the Sync now result), Sync now (Synced / the reason / Needs internet), recovery ("Synced again"), and real sign-in failures. Backing out of Google stays silent (spec §1), decided by `lib/signIn.ts`. The four copies of "Couldn't save" became `common.saveError`, plus `common.deleteError` and `common.undoError`. Loading errors keep their full screen with Retry.
- 2026-11-08 — **Toast look v2** (user: the solid green/red was too dark, and full width was unneeded): every toast is a compact frosted-glass capsule (`.toast-glass` in `globals.css`: 62% tint, blur 24px + saturate 180%, hairline border, soft shadow; solid with Reduce Transparency or More Contrast). It is only as wide as its text and centred, up to the screen width (420 px on desktop). The text uses the theme colours, so contrast holds in both themes; the meaning comes from a small filled badge (green check / red ×). The × sits inline at the end with a 44 px tap area, and Undo/Retry are pill buttons. In dark mode the tint is a lifted grey, not near-black. The rules live in `globals.css` because sonner's own CSS is unlayered, so each selector has to outrank it.
- 2026-11-08 — **Add-sheet draft** (user): an unsaved *new* entry is kept for 2 minutes after the sheet closes (`features/entries/entryDraft.ts`), so leaving to check an SMS doesn't lose the amount. It is kept in localStorage, not memory, so it survives the phone reloading the PWA in the background. It is written on every change and stamped again on close. It is dropped on Save, when emptied, after 2 minutes, and on sign-out. Edits of existing entries are never kept, and a quick-add link's values win over a draft. On restore, wallets and a category that were archived, hidden or deleted in the meantime are cleared.
- 2026-11-08 — **Add-sheet rows** (user): category, wallet and transfer From/To are labelled rows with a themed dropdown each ("Category [Select category]"), using `entries/FieldSelect.tsx`, which replaced `CategorySelect` and the wallet chips. Wallets show their icon too. The date row is only **Today** plus a date picker (Yesterday removed). `docs/mvp-plan.md` §3 updated to match.
- 2026-11-08 — **One corner size: rounded-md** (user). Every radius token (`--radius-sm` … `--radius-4xl`) in `globals.css` resolves to `--radius-md`, so all `rounded-*` classes, shadcn's included, draw the same corner, and so will any added later. Every `rounded-full` became `rounded-md`: chips, the tab bar, the + button, category icons and toast parts. Tiny dots and thin bars still look round, because md is larger than half their size.
- 2026-11-08 — **Sync fix: upload only the server's columns.** The live database showed every wallet upload from the iPhone rejected with HTTP 400 (30 times, 15:08–16:22 UTC), which also kept its entries from uploading and stopped the download step. Cause: the wallet form spread its draft, so its `opening` text box was stored in each wallet it saved, and Supabase rejects a column the table doesn't have. Fixes: `saveWallet` stores named fields only, and `push` sends only the columns in `COLUMNS` (`sync/engine.ts`, `null` for a missing one), so phones that already stored the stray field recover on their next sync. The test fake server now rejects unknown columns and uneven batches the way the real one does, and a test keeps `COLUMNS` in step with the TypeScript types. Separately, the web browser and the iPhone were signed in with **two different Google accounts**, which can never share data.
- 2026-11-09 — **Dev = offline with dummy data; production = real data** (user, instead of a second Supabase project). The Supabase keys moved from `.env.local` to `.env.production.local`, which Next.js loads for builds but never for `npm run dev`. So the dev server has no login or sync and can't touch the real database, while local builds and Vercel (its own env vars) keep sync. On the dev server a fresh database fills itself with the demo set once (`autoAddDemoData`, flag `meta.demo_auto`; a database that already has entries is left alone, and after Remove it stays removed). That call sits behind `process.env.NODE_ENV === "development"`, so production bundles contain no demo code (checked: 0 files in `out/`). Trade-off: login and sync can't be tried on the dev server. Test them on the Vercel site, or copy the keys to `.env.development.local` for a while, which uses the real database.
- 2026-11-09 — **The + moved into the middle of the tab bar** (user): Home · Transactions · **+** · Budgets · More. It is bigger than the tabs (56 px), solid primary instead of glass, raised a little above the bar with a ring in the page colour, and has no label (screen readers hear "Add entry"). Until the data loads it shows disabled, so the bar never shifts. The Transactions totals footer moved up to clear it and no longer needs its right-hand gap.
- 2026-11-09 — **Tab bar v2** (user didn't like the raised square +; "no rounding restriction for the navbar"): the bar is a glass pill (`rounded-full`), the + is a 52 px solid primary circle with a soft shadow, sitting inside the bar (no lift or ring). The tab bar is the only exception to the rounded-md rule, because `rounded-full` isn't a radius token. The Transactions footer and the page's bottom padding went back to fit the slimmer bar.
- 2026-11-09 — **Active tab = filled, bigger icon** (user, instead of a background highlight): the active tab's icon is filled (House, PiggyBank) or drawn with a heavier stroke (the line-only List and Menu), scaled to 120% so nothing shifts, with a bold label in the text colour.
- 2026-11-09 — **Active tab = brand green + dot** (user picked it from four options, replacing the filled icon). The selected tab's icon and label turn the brand green, with a small dot underneath; the others stay grey. New `--brand` token (`bg-brand`/`text-brand`): the app icon's `#0B7A57` in light mode and a lighter green in dark mode, so it stays readable on the dark bar. The dot's space is always reserved, so switching tabs doesn't shift anything.
- 2026-11-09 — **Swipe between tabs** (user): on Home, Transactions, Budgets and More, a quick horizontal swipe on the page goes to the next tab (left) or the previous one (right), like Instagram, and stops at the ends. Rules live in `lib/swipe.ts`. Gestures are left alone when they start in a text field, on something that scrolls sideways (the wallet cards), on `[data-no-swipe]`, or within 24 px of the screen edge (iPhone's own back gesture). It uses touch events only, so a mouse drag on desktop still selects text. The add sheet is outside the swipe area.
- 2026-11-09 — **Instagram-style swipe animation** (user): the page follows the finger, slightly faded; with no tab that way it moves only a quarter as far. On release it slides off (180 ms) while the next tab slides in from the other side (240 ms), or eases back if it doesn't count. It counts past a third of the screen at any speed, or on a flick of at least 60 px within 300 ms, and it must be clearly more horizontal than vertical. Styles are set straight on the page element (no React render per finger move) and cleared after the animation, since a leftover transform would break `position: fixed` inside pages. Reduce Motion skips the animation. The page area uses `touch-action: pan-y pinch-zoom`. `html, body { overflow-x: clip }` stops mobile browsers widening the layout while the page is off to one side, which pushed the fixed tab bar off screen. It has to be on both elements; `clip` keeps sticky working.
- 2026-11-09 — **Bigger Home summary numbers** (user): Income · Spent · Net amounts are now as large as the narrowest card allows, up to 20 px (were 14 px), one size for all three, from the longest value and the measured digit width (English 0.46 em, Bangla 0.56 em per character). About 19.5 px with English digits and 16 px with Bangla at 360 px wide; lakh amounts shrink instead of overflowing.
- 2026-11-09 — **Spending card, iPhone-storage style** (user; of four suggested details they chose only "% of spending"). The donut became one bar split by category (CSS flex, each segment as wide as its spending, at least 4 px so small ones still show), then a list: category icon in its colour, name, amount, and share. Shares come from `sharePercents` (largest remainder), so they always add to exactly 100; a tiny share reads "<1%". Top 5 plus "Others", and tapping a row opens its entries, as before. **Recharts removed**: this was its only chart, and it was one of the largest packages. Spec §6, `CLAUDE.md` stack and the UI skill updated.
- 2026-11-09 — **Spending card made compact** (user found the list too tall; picked "two-column grid" from four layouts). Under the bar, the top 5 plus Others sit in two columns: a colour dot and name, then "amount · %". The icon boxes are gone. The card is about 230 px tall instead of about 390, every cell is still a 44 px tap target, and tapping one still opens its entries.
- 2026-11-09 — **Spending grid with icons** (user: it didn't look nice without them). Each cell has the category icon in a smaller box (`CategoryIcon small`, 32 px), then the name with its share on the right, and the amount below. The share moved up beside the name because a lakh amount in Bangla digits plus its share (109 px) is wider than a cell's text room (101 px). The card is about 242 px tall.
- 2026-11-09 — **Spending cell: amount and share together** (user: the % at the far right, away from the amount, read badly). Each cell is now the icon, then the name in muted text, then the amount in bold with its share right beside it in smaller text ("৳12,000 71%"). A lakh amount in Bangla digits with "১০০%" measures 100 of the 101 px available; if a 10-lakh month ever doesn't fit, only the share is clipped.
- 2026-11-09 — **Home wallet cards sorted by balance, largest first** (user). Only the Home strip: wallet pickers and the Wallets screen keep the user's own order. Equal balances keep the user's order (the sort is stable).
- 2026-11-09 — iOS Shortcut (8b) saves **without opening the app** (user's choice after showing a native app's Log Expense Shortcut): Title → Amount → Category → confirm alert → saved, using the **last-used wallet** (wallet of the newest expense). Shortcuts' Open URL lands in Safari, not the home-screen web app, so the spec's open-the-app version was dropped. The Shortcut calls two `security definer` SQL functions over PostgREST (`shortcut_list`, `shortcut_add`) with the public publishable key plus a personal key; **no Edge Function**. Only the key's SHA-256 is stored, in the server-only table `shortcut_keys` (RLS on, no policies). It is deliberately **not** in `types.ts`/Dexie/`COLUMNS`, since it never syncs. The pop-up texts, category names and the saved message come from the server in the account's language (so they live in SQL, not in bn/en.json). The editable confirm card of native apps (App Intents) needs the Capacitor app (Phase 3). Signed-in users only; needs internet.
- 2026-11-11 — **Google sign-in via Google Identity Services** (user: the sign-in window showed the `supabase.co` address). When `NEXT_PUBLIC_GOOGLE_CLIENT_ID` is set, the welcome/More button is Google's own rendered button; its ID token goes to `supabase.auth.signInWithIdToken` (SHA-256 nonce), so Google says "PaiPoisha" (app name from the OAuth consent screen). Unset = the old redirect flow, unchanged. The client ID is public, a small exception to the "only two env vars" rule. Needs the site's origins under "Authorized JavaScript origins" in Google Cloud. It does not fix iOS home-screen apps lacking Safari's Google cookies.
- 2026-11-13 — **CSV export removed from the plan** (user: not needed; a bank-style statement was tried and also dropped). Spec §8, step 5c and the Settings list no longer mention it.
- 2026-11-13 — **"Update available" toast**. The service worker no longer skips waiting on its own: when a new version has downloaded and an old one is running the page, a toast offers Update; tapping it sends `skip-waiting`, and the page reloads once when the new worker takes over. A running app also checks for a new version whenever it comes back to the foreground. Not shown on a first visit; never runs in dev (no worker there).
- 2026-11-13 — **Native selects removed**: the budget category picker and More "Month starts on" now use the themed `Select` (`FieldSelect` / `ui/select`), so lists follow dark mode and the digit setting.
- 2026-11-13 — **Privacy policy, terms and account deletion** (spec §11). One public page `/privacy/` holds both the policy and the terms (`/privacy/#terms`); the welcome gate skips it so anyone (and Google's consent-screen check) can open it. Contact is the GitHub issues page (user's choice). The policy names no database, region or host, only "the cloud" and Google (user, 2026-11-13).
